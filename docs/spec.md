# ブレイキング練習動画 自動トリミングPWA — MVP仕様書

Nov 5, 2026

## 実装ルール

本書はMVPの実装仕様である。以下のルールに従って実装すること。

- 「開発フェーズ」の順に1フェーズずつ実装する。各フェーズの終わりで作業を止め、実装内容と動作確認の手順をユーザーに報告して、確認を待つ
- 「MVP対象外」の機能は実装しない
- 仕様にない判断のうち、挙動やUIに影響するものは実装前にユーザーに質問する。軽微なものは判断してよいが、READMEの「仮決め事項」に記録する
- 解析ロジック（スコア算出・区間分割）はUIに依存しない純粋関数のモジュールにし、区間分割には単体テスト（Vitest）を書く。将来Swiftへ移植しやすくするため
- パラメータはすべて `src/config.ts` に集約し、コード内に数値を直書きしない
- UI文言とコードコメントは日本語。スマホ縦画面を基準にレイアウトする
- 空の状態・解析失敗・非対応形式などのエラーは、画面上に日本語で理由を表示する

## 概要

ブレイキングの練習動画から「動いている区間」だけを自動で切り出し、クリップごとに保存できるPWAを作る。MVPは「撮影済みの動画ファイルを入力→自動分割→書き出し」まで。

- **解決する課題**：録画開始〜動き出し、動き終わり〜録画停止の無駄な区間のトリミングと、アイデア出し動画を「考えている間」で分割する手作業をなくす
- **対象ユーザー**：ユーザー本人のみ（個人利用。ログインや多言語対応は不要）
- **対象端末**：iPhoneのSafari（ホーム画面に追加して使用）。PCブラウザでも動作すること
- **UI言語：日本語**
- **費用**：有料のAPI・サービスは使わない。サーバーサイド処理も持たない

## 技術スタック

すべてブラウザ内で処理し、サーバーへ動画を送らない構成にする。

| 役割 | 採用技術 | 備考 |
| --- | --- | --- |
| UI | Vite + React + TypeScript | PWA化にはvite-plugin-pwa |
| 動画入力 | `<input type="file" accept="video/*">` | 写真ライブラリから選択 |
| フレーム取得 | `<video>` + canvas（seek方式） | 10fps・短辺240px程度に縮小して解析 |
| 骨格推定 | @mediapipe/tasks-vision の Pose Landmarker（liteモデル） | 学習済みモデルをそのまま使う |
| フレーム差分 | canvasのImageDataで画素比較 | 骨格が取れないときの補完 |
| グラフ表示 | Chart.js | 動きスコアと区間の可視化 |
| 切り出し | @ffmpeg/ffmpeg（ffmpeg.wasm。SharedArrayBuffer不要のシングルスレッド版） | 再エンコードなしの `-c copy` |
| 保存 | Web Share API（`navigator.share` でファイル共有） | 共有シート→「ビデオを保存」 |
| ホスティング | GitHub Pages（GitHub Actionsで自動デプロイ） | HTTPS必須 |

## 画面構成と機能

画面は3つで、上から順に進む一本道のフローとする。

1. **動画選択画面**
   - 動画を1本選ぶ（複数本の一括処理は対象外）
   - モード選択：「アイデア出し（細かく分割）」「通し練習（前後のみトリム）」（v0.5.0の後、ユーザーの判断でモード選択をなくし、アイデア出しだけにした。通し練習の区間計算は残してある）
   - 「解析開始」ボタン。解析中は進捗率と「画面を閉じないで」の注意を表示
2. **解析結果画面**
   - 動きスコアの折れ線グラフ（横軸：秒）に、切り出し区間を色付きの帯で重ねる（フリーズ判定区間は別色）
   - グラフをタップするとその時刻にプレビューが飛ぶ
   - パラメータのスライダー（開始閾値、終了閾値、区切り静止秒数、余白）。変更すると再解析なしで区間だけ再計算
   - 動きスコアをCSVで書き出すデバッグボタン（閾値調整用）
3. **クリップ一覧画面**
   - クリップごとにサムネイル、開始時刻、長さを表示
   - タップでプレビュー再生、チェックボックスで「残す／捨てる」を選択
   - 「選択したクリップを保存」で書き出し

## 解析・分割アルゴリズム

判定はルールベースとし、自前の学習は行わない。解析（重い）と分割（軽い）を分離し、パラメータ変更時は分割だけをやり直す。

### ステップ1：動きスコアの算出（10fps）

- **対象人物**：Pose Landmarkerを最大人数2で実行し、バウンディングボックスが最大の人物を本人とみなす（他人・鏡像の対策はMVPではここまで）
- **骨格スコア**：頭・肩・肘・手首・腰・膝・足首のうち、信頼度0.5以上の関節の前フレームからの移動量を平均し、体の大きさ（バウンディングボックスの対角線）で割って正規化。各関節の移動量からは体全体の移動（全関節の平均移動量）を差し引き、歩いて移動するだけの時間を動きと判定しない
- **差分スコア**：グレースケール画素の差が25以上の画素の割合（直前に本人を検出できていればその周辺範囲に限定）
- **統合**：信頼できる関節が6個以上あれば骨格スコア、なければ差分スコアを採用。0.5秒の移動平均で平滑化
- **除外**：撮影開始・終了時にカメラまで歩く時間を区間に含めないため、次の時間はスコアを0にする
  - カメラ付近：画面全体で変化した画素の割合が10%以上で、かつ本人の骨格が取れていないか体の高さが画面の60%以上のフレームと、その前後1秒（撮影ボタンを押しに行く・カメラの前を通る）。離れて踊っている間のカメラの揺れ・照明の変化では除外しない
  - 除外した時間はグラフに灰色の帯で表示する
  - 本人の骨格を最初に検出する前・最後に検出した後（体の一部しか写らず差分スコアだけが跳ね上がるため）。一度も検出できなかった動画は差分スコアだけで判定する
- **姿勢情報**：各フレームで体幹の角度（肩の中点→腰の中点のベクトルと鉛直方向の角度）も記録する

### ステップ2：区間の切り出し

1. スコアが開始閾値を上回る状態が0.3秒続いたら「動き開始」
2. スコアが終了閾値を下回る状態が区切り静止秒数続いたら「動き終了」（開始＞終了という異なる閾値でチラつきを防ぐ）
3. **フリーズ判定**：静止の直前1秒に開始閾値の2倍以上の動きがあり、かつ体幹が鉛直から45度以上傾いていれば、その静止はフリーズとして区間に含める（最大5秒）
4. 各区間の前後に余白を付ける
5. 間隔が結合秒数未満の隣接区間は1つにまとめ、最小クリップ長未満の区間は捨てる
   - 余白を付ける前に、骨格で確かめた動き（骨格スコアが開始閾値以上のフレーム）が合計0.3秒未満の区間は捨てる。カメラの近くを通る足だけが写るなど、差分スコアだけで動きと判定された区間を除くため（一度も骨格を検出できなかった動画は除く）
6. 通し練習モードでは、最初の開始〜最後の終了を1クリップとして出力する。最初と最後を探すときは、区切り静止秒数を最大2秒として区間を分けてから5の判定をする（撮影直後の移動と踊りがつながらないように）

### パラメータ初期値

以下は暫定値。`src/config.ts` にモード別の定数として定義し、解析結果画面のスライダーで変更できるようにする。開始閾値はフェーズ1のCSVを見てユーザーが決める。

| パラメータ | アイデア出し | 通し練習 |
| --- | --- | --- |
| 開始閾値 | 0.05（暫定） | 同左 |
| 終了閾値 | 開始閾値の60% | 同左 |
| 区切り静止秒数 | 2.0秒 | 5.0秒 |
| 余白（前／後） | 0.5秒／0.7秒 | 1.0秒／1.0秒 |
| 結合秒数 | 1.0秒 | 3.0秒 |
| 最小クリップ長 | 1.5秒 | 3.0秒 |

## 書き出し・保存

再エンコードせずに切り出し、共有シート経由で写真アプリに保存する。

- 切り出しはffmpeg.wasmで `-ss <開始> -to <終了> -c copy` を実行。切り位置がキーフレーム単位で数百ミリ秒ずれるのは許容する
- 出力形式は元動画と同じコンテナ（iPhoneなら.mov、中身はHEVC）
- ファイル名：`<元ファイル名>_<連番2桁>_<開始秒>s.mov`（例：`IMG_1234_03_75s.mov`）
- 保存は `navigator.share({ files })` で複数ファイルをまとめて渡す。共有非対応の環境（PC）ではダウンロードに切り替える
- 元動画は変更・削除しない

## 非機能要件・制約

最大の制約はiPhone Safariのメモリ上限なので、対応する動画を絞る。ユーザーは4Kで撮影することが多いため4Kまで対応し、1080pへの変換（再エンコード）は行わない（ブラウザ内では処理時間が大きく、メモリの問題も解決しないため）。

- **対応動画**：4K（2160p）まで・30〜60fps・10分以内を正式サポート。それを超える動画は警告を出して続行を確認する
- **解析速度の目標**：動画の長さ以内（1分の動画を1分以内）
- **メモリ**：ffmpeg.wasmには元動画を1回だけ読み込み、書き出し後は不要なファイルを削除する。4K動画（数百MB）をメモリに丸ごと複製しないよう、WORKERFSでのマウントなど必要な部分だけ読む方式を優先する
- **中断への備え**：解析中にアプリを切り替えると処理が止まるため、画面に注意を表示し、可能ならScreen Wake Lockでスリープを防ぐ
- **プライバシー**：動画は端末外に送信しない。外部通信はアプリ・モデルファイルの読み込みのみ
- **オフライン**：初回表示時にアプリ本体・モデル・ffmpeg.wasmをすべてキャッシュし、スタジオで電波が弱くても使えるようにする

## 開発フェーズ

最初に「動きスコアのグラフ表示」まで作り、実際の練習動画で閾値を決めてから分割に進む。完了条件はユーザーがiPhone実機で確認する。

- [x] **フェーズ1：動きスコアの可視化**— 動画選択→解析→グラフ表示→CSV出力。完了条件：ユーザーの練習動画3本以上で、動いている区間とフリーズがグラフ上で見分けられる
- [x] **フェーズ2：自動分割**— 区間算出・フリーズ判定・スライダー調整。完了条件：調整後の初期値で、ユーザーが手作業で切る位置とほぼ一致する
- [x] **フェーズ3：書き出し**— クリップ一覧・選択・ffmpeg.wasmでの切り出し・共有シート保存。最初に「4K動画から1クリップを切り出して保存できるか」をiPhone実機で検証してから本実装に進む。完了条件：iPhoneで写真アプリに保存できる
- [x] **フェーズ4：PWA化と公開**— マニフェスト・Service Worker・ホスティング。完了条件：ホーム画面から起動し、スタジオで実用できる

MVP（フェーズ1〜4）は `v0.4.0` で完成。以降はMVP後の拡張として進める（「タイムライン編集（MVP後の拡張）」の章を参照）。

- [x] **フェーズ5：タイムライン表示と1画面化**— 解析結果画面とクリップ一覧画面を1つの編集画面にまとめ、コマの帯・動きの波形・区間の帯を重ねたタイムラインを表示する。拡大・縮小、再生位置との連動、タップでのシーク。書き出しは既存のまとめて保存を使う。最初にiPhoneのブラウザでキーフレーム時刻を取得できるかを検証する。完了条件：iPhoneで、タイムラインを見ながら区間を選んで保存できる
- [ ] **フェーズ6：区間の手動編集**— 端のドラッグでの伸縮（開始はキーフレームに吸着）、区間の追加・削除・分割・結合。完了条件：AIの提案を手で直して、思い通りの範囲を保存できる

### フェーズ1の詳細

- Vite + React + TypeScriptでプロジェクトを作成し、動画選択画面と解析結果画面（グラフとCSV出力のみ、スライダーと区間表示はフェーズ2）を実装する
- ステップ1の動きスコアと体幹角度を算出し、統合スコアを折れ線グラフで表示する
- CSVの列：時刻（秒）、骨格スコア、差分スコア、画面全体の差分、統合スコア（平滑化後）、採用したスコア種別、体幹角度、検出人数
- READMEに、ローカル起動方法とiPhone実機で確認する手順（同一Wi-Fiでのアクセスなど）を書く

フェーズ2以降は、本書の該当セクションに従って実装する。

## タイムライン編集（MVP後の拡張）

Final Cut Pro などのタイムラインのように、AIが判定した区間を土台に、人が範囲を微調整して複数の区間をまとめて書き出せるようにする。ユーザーと決めた方針は次のとおり。

### 画面構成
- 「解析結果画面」と「クリップ一覧画面」を1つの**編集画面**にまとめる。画面は「動画選択 → 解析中 → 編集」の3つになる
- 編集画面は、上にプレビュー動画、間を空けずに下にタイムラインを置く（CapCut・Instagram Edits のような黒基調の編集画面）。書き出し（写真に保存）は別画面にする
- プレビューにシークバーは出さない（タイムラインと役割が重なるため）。タップで再生／停止、長押しの間だけ2倍速で再生する
- 画面上の説明文は置かず、必要な説明はホバー（title）で出す
- タイムラインは次の3段を同じ時間軸で重ねる
  1. コマの帯（解析で取り出したコマを縮小して並べる。動画を再デコードしない）
  2. 動きの波形（今のグラフの動きスコアと閾値線）
  3. 区間の帯（AIの提案と手での調整結果。フリーズ・数えなかった時間も色分け）
- 再生位置の縦線はタイムラインの中央に固定し、タイムラインをなぞってスクロールするとシークする。ピンチで拡大・縮小する
- 各区間に「残す／捨てる」を持たせ、残す区間をまとめて保存する（書き出し・分割保存の仕組みはフェーズ3のものを使う）
- 区間の帯をタップするとその区間を頭から再生し（終わりで止める）、ダブルタップで「残す／捨てる」を切り替える。区間の一覧は置かない
- 保存は書き出し画面で1タップで共有シートを開く。書き出し画面を開いたら裏で先に書き出しておき、「写真に保存」のタップで書き出し済みのファイルを渡す（共有シートはタップ直後にしか開けないため）

### 切り位置の精度
- 再エンコードしない切り出し（`-c copy`）は、開始位置をキーフレーム（iPhoneの動画で約1秒ごと）にしか置けない
- そのため**開始位置のつまみはキーフレームに吸着**させ、画面で見た位置と書き出し結果を一致させる。終わり位置は自由に動かせる
- キーフレームの時刻は、書き出しと同じ ffmpeg.wasm（ffprobe）でパケット情報から読む（映像のデコードはしない）
- 頭だけ再エンコードして正確に切る方式は、iPhoneのブラウザでは4Kの処理が重いため採用しない

### 編集操作
- 区間の端をドラッグして伸縮する（タップで選んだ区間の両端につまみを出す）。伸ばして他の区間と重なったら自動で合体する
- 区間を追加する（再生位置から一定秒数の区間を作る）・削除する
- 区間を再生位置で2つに分割する・隣り合う区間を結合する
- 区間が重ならないようにする（重なったら結合する）

### AIの提案と手での調整の関係
- スライダー（開始閾値など）はAIの提案を作り直すときだけ使う
- 手で調整した後にスライダーを動かすときは、「手で調整した内容が消えます」と確認してから作り直す

## MVP対象外（将来機能）

以下は実装しないこと。ただし後から追加しやすい構造にしておく。

- 最初のフレームで自分をタップして指定し、その人物だけを追跡する（複数人練習対策）
- 切り出し対象のモード選択：「指定した人物が踊っている箇所だけ」「誰かが踊っている範囲（写っている全員の動きの最大値で判定）」。区間分割はスコア列を入力とする純粋関数にし、どの人物のスコアを使うかを差し替えられるようにしておく
- 鏡などを指でなぞって「解析対象外エリア」に指定する
- 切り位置の手動修正と、その修正履歴を使ったパラメータ自動調整
- 「踊っている／考えている／フリーズ」の動作分類モデル（修正履歴が溜まってから）
- 拍手や声で区切りを入れる補助機能
- アプリ内での撮影と、撮影直後の自動処理
- iPhoneネイティブアプリ（Swift）への移植
