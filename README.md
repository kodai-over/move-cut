# MoveCut

ブレイキングの練習動画から「動いている区間」だけを自動で切り出すPWA。動画はすべて端末内で処理し、外部に送信しない。

- 公開URL: https://kodai-over.github.io/move-cut/
- 仕様: [docs/spec.md](docs/spec.md)

## ローカル起動

```bash
npm install
npm run dev
```

`npm run dev` / `npm run build` の前に `scripts/fetch-assets.mjs` が自動で走り、MediaPipe のWASMとPoseモデル（lite）を `public/` に配置する（初回のみモデルをダウンロード）。

## テスト

```bash
npm test
```

## iPhone実機での確認

- 基本は `main` マージ後に公開URLをSafariで開いて確認する（HTTPSのため共有シート・Wake Lockも動作する）
- 開発中に確認したい場合: Macと同じWi-FiのiPhoneで、`npm run dev` が表示する `Network:` のURL（`http://<MacのIP>:5173/move-cut/`）を開く（HTTPのため共有シート・Wake Lockは動かない）

### フェーズ1の確認手順

1. 公開URLを開き「動画を選ぶ」→ 写真ライブラリから練習動画を選ぶ
2. モードを選んで「解析開始」。解析中は画面を開いたままにする
3. 結果画面のグラフで、動いている区間（青線が高い）とフリーズ（青線が低く、灰色の体幹角度が大きい）を見分けられるか確認する。グラフをタップすると動画がその時刻に移動する
4. 「CSVを書き出す」で動きスコアを保存し、開始閾値の検討に使う

### フェーズ2の確認手順

1. 公開URLで練習動画を解析する（モードで初期値が変わる）
2. 結果画面のグラフで、青い帯（切り出し区間）とオレンジの帯（フリーズ）が、自分で切りたい位置とほぼ合っているか確認する。区間の一覧をタップすると、その開始位置に移動する
3. 合わない場合はスライダーで調整し、合ったときの値を教える（初期値の見直しに使う）

### フェーズ3の確認手順

1. 公開URLで、iPhoneで撮った4K動画を解析し、結果画面の「クリップ一覧へ」をタップする
2. クリップ一覧で、サムネイル・開始時刻・長さが表示されること、タップでそのクリップだけがプレビュー再生されることを確認する
3. 残すクリップにチェックを付けて「選択したクリップを保存」→ 書き出し後に「写真に保存する」→ 共有シートの「ビデオを保存」で、選んだクリップがまとめて写真アプリに保存されることを確認する

### フェーズ4の確認手順

1. Wi-Fiなど電波のよい場所で公開URLをSafariで開き、「電波がなくても使えるようになりました」と出るまで待つ（初回は約52MBを読み込む）
2. 共有ボタン →「ホーム画面に追加」でアイコンを置き、ホーム画面から起動するとSafariの枠なしで開くことを確認する
3. 機内モードにしてホーム画面から起動し、解析 → クリップ一覧 → 保存まで使えることを確認する

ホーム画面に追加せずSafariのタブだけで使っていると、しばらく（目安7日）開かないうちにキャッシュが消され、電波なしでは使えなくなることがある。初回は約52MBを読み込むので、Wi-Fiで開くとよい

### フェーズ5の確認手順

1. 公開URLで練習動画を解析すると、編集画面（上にプレビュー、下にタイムライン）が開く
2. タイムラインに、コマの帯・動きの波形・区間の帯（青）が同じ時間軸で並ぶこと、「＋」「－」「全体」で拡大・縮小、横になぞってスクロール、タップでその時刻にプレビューが移ることを確認する
3. 拡大すると区間の帯の下にキーフレームの目盛り（約1秒ごと）が出ることを確認する（フェーズ6の開始位置の吸着に使う）
4. 下の一覧でクリップをタップするとそのクリップだけ再生され、チェックで残す／捨てるを選んで「選択したクリップを保存」で保存できることを確認する

## 仮決め事項

仕様にない軽微な判断の記録。

- **モデル・WASMの配信元**: CDNではなくアプリと同じオリジン（GitHub Pages）から配信する。ビルド時に `scripts/fetch-assets.mjs` で取得し、リポジトリには含めない
- **骨格推定の実行**: GPU（WebGL）で初期化し、失敗したらCPUで実行する
- **信頼度**: 関節の信頼度には MediaPipe の `visibility` を使う
- **バウンディングボックス**: 本人選択と正規化には、33点すべてのランドマークを囲む矩形を使う
- **本人の追跡（仕様変更・ユーザー確認済み）**: 仕様の「毎フレーム最大の人物」では練習中のスタジオで他人に判定が移るため、最初は最大の人物を選び、以降は前フレームの本人に最も近い人物（矩形中心の移動が対角線の0.8倍以内）を追う。見失ったら別人に乗り換えず待ち、2秒以上見失ったら最大の人物を選び直す。選び直すのは、最後に見た本人の大きさ（画面対角線の0.3倍が上限）の半分以上に写っている人物に限る（奥の小さな他人に乗り換えないため）。追跡が途切れたフレームは骨格スコアを計算せず差分スコアを使う（`ANALYSIS.track*`）
- **骨格スコアの関節**: 頭は鼻（0番）で代表する。前後両フレームで信頼度0.5以上の関節だけを数え、6個以上なら骨格スコアを採用する
- **差分スコアの範囲**: 直前フレームの本人の矩形を各辺25%広げた範囲に限定する（`ANALYSIS.diffRoiMargin`）
- **先頭フレーム**: 比較対象がないため統合スコアは0（採用スコア「なし」）
- **移動平均**: 中心化した5フレーム（0.5秒）窓。両端は窓を縮める
- **体幹角度**: 直立0度・横倒し90度・逆立ち180度
- **CSV**: UTF-8（BOM付き）。ファイル名は `<元ファイル名>_motion.csv`
- **サポート範囲外の動画**: 解析開始時に確認ダイアログを出す。対応解像度はユーザー確認のうえ仕様を4Kまでに変更済み
- **解析結果画面（フェーズ1）**: ユーザー確認のうえ、プレビュー動画とグラフタップでのシーク、体幹角度の表示を前倒しで実装
- **開始閾値の初期値**: フェーズ1の実動画で静止 0.02〜0.06・ダンス 0.08〜0.18 だったため、仕様の暫定値 0.05 から 0.08 に変更（終了閾値は60%の 0.048）
- **区間判定の細部**: 「0.3秒続いた」は10fpsで3サンプル連続。開始時刻は上回った最初の時刻、終了時刻は下回った最初の時刻。フリーズは静止の始まりで判定し、体幹が起きる・5秒を超えるまでを区間に含め、その後の静止から区切り静止秒数を数える。0.5秒未満の一瞬の傾きはフリーズとみなさない（`SEGMENT.freezeMinSec`）
- **余白のスライダー**: 前と後で初期値が違うため、仕様の「余白」を前・後の2本に分けた。終了閾値は開始閾値を超えないよう制限する。グラフのスコア軸は、閾値線が枠外に消えないよう開始閾値の1.2倍以上を表示する
- **区間の一覧**: クリップ一覧画面（フェーズ3）の前段として、結果画面に区間の時刻を並べ、タップでその位置にシークできるようにした
- **歩きとカメラへの移動の除外（仕様変更・ユーザー確認済み）**: 「撮影ボタンを押して移動→試す→考える→試す→カメラに戻る」のうち、移動を確実にカットするため、骨格スコアから体全体の移動を差し引き、カメラ付近（画面全体の変化10%以上で、骨格が取れないか体の高さが画面の60%以上のフレームと前後1秒。グラフに灰色で表示）と本人の骨格の検出前後をスコア0にする（`ANALYSIS.nearCamera*`）。カメラのすぐ近く（体が画面の大部分を占める距離）で踊った時間もカットされる
- **ffmpeg.wasm**: シングルスレッド版のコアを使う（GitHub Pages では SharedArrayBuffer に必要なヘッダーを付けられないため。再エンコードしないコピーなので速度は問題ない）。コアはモデルと同じくアプリと同じオリジンから配信する
- **切り出しの引数**: 仕様の `-to <終了>` の代わりに、入力前の `-ss <開始>` と長さ `-t` で指定する（入力前の `-ss` と組み合わせたときの `-to` の解釈の違いを避けるため）。映像1本と音声1本だけを残し、iPhoneの .mov に含まれるメタデータ用トラックは捨てる。撮影日時などのメタデータは引き継ぐ
- **保存ボタン**: 共有シートはタップ直後にしか開けないため、書き出しが終わってから「写真に保存する」ボタンを別に押す
- **骨格で確かめた動きがない区間を捨てる（ユーザーの動画で確認のうえ追加）**: 床置きの低いカメラでは、カメラの近くを通るときに足だけが写り、画面全体の変化が10%未満のまま差分スコアだけが跳ね上がって区間になっていた。区間内で骨格スコアが開始閾値以上のフレームが合計0.3秒未満なら捨てる（`SEGMENT.minSkeletonEvidenceSec`）。体が画面端で切れているかで判定する案は、低いカメラだと逆立ちの手が上端に届くため採用しなかった
- **通し練習モードの区切り静止秒数**: 最初〜最後を1区間にするモードでは区切り静止秒数の影響がほぼないため、スライダーを表示しない
- **まとめて保存の分割**: iPhoneのSafariのメモリ上限に備え、1回の共有シートで渡すクリップは推定合計400MBまでにし、超える場合は何回かに分けて書き出し・保存する（`EXPORT.maxBatchBytes`。推定は元動画のサイズ÷長さ×クリップの長さ）。共有シートをキャンセルしたら、もう一度保存するか保存せずに次へ進むかを選べる
- **クリップ一覧**: 仮の「区間1を書き出す（動作確認）」ボタンを置き換えた。サムネイルは余白の分だけ後ろ（開始から0.7秒）のコマを使う。区間のパラメータは一覧から解析結果に戻っても保つ
- **オフライン対応**: アプリ本体に加えて、骨格推定モデル・MediaPipe・ffmpeg.wasm（合計約52MB）も最初の表示で事前キャッシュする。仕様の「初回以降はキャッシュ」より一歩進め、書き出しを一度も使っていなくても電波なしで使えるようにした
- **更新**: 新しいバージョンがあっても自動で再読み込みせず、動画選択画面に「更新する」ボタンを出す（解析・書き出しの途中で止めないため）
- **アイコン**: 青地に、再生マークを前後の切り位置（括弧）で挟んだ図柄（`public/icons/`。SVGから rsvg-convert でPNGを作成）
- **編集画面（フェーズ5）**: 解析結果画面とクリップ一覧画面を1つにまとめた。グラフ（Chart.js）はタイムラインの波形に置き換え、体幹角度の線は出さない（フリーズの帯で代わりに示す）。サムネイルは解析中に取り出したコマ（1秒ごと・高さ48px）を使う。「AIの提案を調整する」は折りたたみにした
- **キーフレームの読み取り**: 編集画面を開いたときに ffprobe でパケット情報を読む（実測で218秒の動画が約2秒）。ffmpeg.wasm の ffprobe は成功しても終了コードが0にならないことがあるため、出力の中身で判定する
